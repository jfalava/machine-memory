## Usage

```sh
machine-memory size <content> [--tags <tags>] [--context <context>]
machine-memory size --from-file <path> [--tags <tags>] [--context <context>]
```

## Size limit

A memory's embedded text is at most **2,000 UTF-8 bytes**. The embedded text is
the content, plus a `Tags:` line and a `Context:` line when those fields are
set. Memory type, status, and certainty are not counted.

`size` measures a prospective memory against that limit **without touching the
database**. `add` and `update` refuse a memory over the limit before anything is
stored, and `--dry-run` on either prints the same report:

```sh
machine-memory size "<text>" --tags "area:cli" --context "why it matters"
machine-memory add "<text>" --dry-run --remote
machine-memory update <id> "<text>" --dry-run --remote
```

```json
{
  "bytes": 49,
  "max_bytes": 2000,
  "within_budget": true,
  "over_by_bytes": 0,
  "remaining_bytes": 1951,
  "parts": { "content": 6, "tags": 15, "context": 28 }
}
```

`parts` is the bytes each field contributes, with its label and line break.
When a memory is over the limit, `over_by_bytes` is the number of bytes to
remove and `remaining_bytes` is negative.

Every successful `add` and `update` reports `size` with `bytes` and
`remaining_bytes`, so no flag is needed to see how much room a record has left.

## Exit code

The command exits `1` when the memory is over the limit, so scripts can
preflight writes:

```sh
machine-memory size "$(cat long-note.txt)" || echo "would be refused"
```

## Options

Pass `--tags` and `--context` with the values the real write will use, because
they count toward the limit. `--from-file` reads the content from a file.
`--local` and `--remote` are accepted so the command can be called like the
others; no database is accessed.
