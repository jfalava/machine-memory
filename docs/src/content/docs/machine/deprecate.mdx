## Usage

```sh
machine-memory deprecate <id|id,id,...> (--local|--remote)
machine-memory deprecate --match "old topic" --superseded-by <id> (--local|--remote)
```

Without `--superseded-by`, targeted memories receive the `deprecated` status.
With it, they receive `superseded_by` and point at the canonical replacement.
`last_updated_by` records the [writer](/machine/add#who-wrote-it) that made
the change; `--updated-by` names another.

The command accepts either IDs or an active-memory `--match` query. It returns
the changed rows, missing IDs for batch requests, and the count of updated
memories. Output flags: `--brief` prints `{id, status}`, `--json-min`/`--quiet`
print `{id}` for single targets and compact `{deprecated_ids, not_found,
count}` payloads for batches.

Retiring a premise can leave other memories relying on it. The response adds
`review_candidates` (minimal output: `review_candidate_ids`): up to five
active memories that refer to the deprecated memory by ID (`cites: true`), or
that name at least two paths, flags or symbols of its content that at most
three other memories each mention (`shared_identifiers`). The
`--superseded-by` replacement is excluded. They are candidates: read each one,
and update or deprecate it only when it relies on the retired premise.
