## Usage

```sh
machine-memory add <content> (--local|--remote)
machine-memory add --from-file <path> (--local|--remote)
```

`add` creates an active memory for the current repository. It can store tags,
context, memory type, certainty, source agent, references, and an optional
expiry window. The command checks for potential conflicts and, for status
memories, reports older overlapping status entries that may need deprecation.

Use `--upsert-match <query>` when an existing strong match should be updated
instead of creating a second memory:

```sh
machine-memory add "The API uses remote D1" \
  --upsert-match "remote D1 API" --type decision (--local|--remote)
```

The match is strong only when its similarity is at least `0.62` **and** its
score reaches the threshold (`--upsert-threshold <0-100>`, default `32`,
override via the `MACHINE_MEMORY_UPSERT_MIN_SCORE` environment variable).
When a record matches but fails that bar, `add` refuses to silently create a
near-duplicate: non-interactive runs must pass `--force` to create a new
record anyway, and interactive runs ask for confirmation. Preflight with
`--dry-run` to see what would be matched:

```sh
machine-memory add "New wording" --upsert-match "topic" \
  --dry-run (--local|--remote)
# {"command":"add","dry_run":true,"action":"update",
#  "would_match":{"id":42,"score":88,"similarity":0.91,"content_head":"..."},
#  "size":{...}}
```

`--dry-run` never writes: without `--upsert-match` it prints the size report
for a would-be `create`, and with it, the candidate plus the prospective
merged-document size. `action` is what the real write does: `update` for a
strong match, `create` when nothing matches or `--force` overrides a weak
match, and `refuse` for a weak match without `--force`. It exits `1` when the
text is over budget or the write would be refused.

Content that is empty, `null` or `undefined` is refused: those are missing
values turned into text by a shell or a script.

## Options

`--path` enables path-driven tag suggestions. `--tags` and `--context` store
retrieval metadata. `--type` accepts `decision`, `convention`, `gotcha`,
`preference`, `constraint`, `reference`, or `status`. `--certainty` accepts
`verified`, `inferred`, or `speculative`. `--refs` accepts JSON or CSV
references, and `--expires-after-days` is useful for transient status.

## Evidence

Certainty says how sure a claim is; evidence says what it rests on.
`--evidence` takes a comma-separated list of the kinds that were actually
established:

| Kind                      | Meaning                                                 |
| ------------------------- | ------------------------------------------------------- |
| `user_requirement`        | The user explicitly asked for it or stated a preference |
| `observed_implementation` | The code currently behaves this way                     |
| `verified_mechanism`      | The underlying technical mechanism was confirmed        |
| `tested_behavior`         | End-user behavior was exercised in tests or real use    |

Observing the implementation does not establish intent or cross-platform
behavior, so record what is still unconfirmed with `--validation-gaps`: one
plain-text gap, or a JSON array of up to 16 gaps of at most 300 characters.

```sh
machine-memory add "Admin shortcuts fire only inside focused forms" \
  --type decision --certainty verified --evidence observed_implementation \
  --validation-gaps '["User intent unconfirmed","Safari and Windows untested"]' \
  (--local|--remote)
```

`--certainty verified` is rejected unless at least one evidence kind is given.
Evidence and gaps are stored metadata only: they are not embedded and do not
count toward the size limit. `get` and `list` return them as arrays,
and `--json-min` summaries include `evidence` plus a `validation_gap_count`.

`--from-file` and inline content are mutually exclusive. `--no-conflicts`
suppresses conflict details; `--brief`, `--json-min`, and `--quiet` select
smaller responses. A forced create over a weak match includes an
`upsert_match` object in the response.

## Size limit

A memory's embedded text (content, plus `Tags:` and `Context:` lines when set)
is at most 2,000 UTF-8 bytes. A longer write is refused before anything is
stored, and the error leads with the number of bytes to remove:

```sh
machine-memory add "long content..." --tags "area:cli" --remote
# error: Memory is over by 728 bytes of 2,000: content 2,713, tags 15,
#        context 0 bytes. Shorten it, or split it into one record per fact.
#        Nothing was written.
```

Preflight any text without writing with [`size`](/machine/size) or
`add --dry-run`. Every successful write reports how much room the record has
left, in every output mode:

```json
{ "id": 42, "size": { "bytes": 108, "remaining_bytes": 1892 } }
```
