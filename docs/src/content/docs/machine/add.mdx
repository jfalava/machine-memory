## Usage

```sh
machine-memory add <content> (--local|--remote)
machine-memory add --from-file <path> (--local|--remote)
```

`add` creates an active memory for the current repository. It can store tags,
context, memory type, certainty, source agent, references, and an optional
expiry window. For status memories it reports older overlapping status entries
that may need deprecation.

## Duplicates and related records

A plain `add` is refused when an active memory already states nearly the same
thing: its text overlap with the new memory is `0.78` or more, the threshold
[`doctor`](/machine/doctor) uses for near-duplicates. The error names that
memory and the two ways forward:

```sh
machine-memory add "Deploys run through scripts/deploy.sh" (--local|--remote)
# error: Memory #12 already states nearly the same thing (text_overlap 0.86,
#        at or above 0.78). Nothing was written. To change that record, repeat
#        the add with --update-id 12. If this is a different fact, repeat it
#        with --create-new.
```

- `--update-id <id>` replaces the content of that memory. Fields you omit
  (tags, context, type, certainty) keep their stored values.
- `--create-new` says you read the existing memories and this is a different
  fact. It creates the record.

When the new memory is not a duplicate, the response lists `related`: the
active memories that strongly match it, so you can check that it does not
repeat or contradict them. The field is absent when nothing matches strongly.

## Candidates for a parent agent

When a parent agent owns memory, a child agent returns its findings instead of
writing them. `--emit-candidate <file>` makes that a file:

```sh
machine-memory add "Lint runs oxlint with the anti-slop plugin" \
  --type reference --tags area:lint \
  --emit-candidate findings.json (--local|--remote)
```

The command checks the memory the way a real `add` does (size, evidence,
near-duplicates), prints the `--dry-run` output, and writes nothing to the
database. A memory that passes is appended to the JSON array in the file, and
the output reports `candidate_emitted: true` and `candidates_in_file`. A
memory that a real `add` would refuse, or that would update an existing
memory, is not appended: the command exits `1` and `note` says why.

The parent writes the file with
[`import <file> --review`](/machine/import#reviewing-candidates), which
reports each candidate as written or declined.

## Who wrote it

Every write records its writer: `source_agent` is who created the memory and
`last_updated_by` who last changed it, as `<agent>:<thread>`, such as
`amp:T-1234`. The CLI reads the writer from the agent harness it runs under
(Amp, Claude Code or Codex). Set `MACHINE_MEMORY_AGENT` to name it yourself,
or pass `--source-agent` and `--updated-by` on one write. Outside a harness
with neither set, both stay empty.

[`list`](/machine/list), [`export`](/machine/export) and
[`checkpoint`](/machine/checkpoint) take `--mine` to read only what the
current session wrote, and `--by <writer>` for another writer.

## Upsert by topic

Use `--upsert-match <query>` when you do not know the ID and an existing strong
match should be updated instead of creating a second memory:

```sh
machine-memory add "The API uses remote D1" \
  --upsert-match "remote D1 API" --type decision (--local|--remote)
```

Two numbers decide whether the match is strong:

- `rank_score` (0 to 100): how well the record matches the query. It must
  reach the threshold (`--upsert-threshold <0-100>`, default `50`, override
  via the `MACHINE_MEMORY_UPSERT_MIN_SCORE` environment variable).
- `text_overlap` (0 to 1): the share of terms the record and the new content
  have in common. It must be at least `0.62`.

A record can rank high for the query and still share little with the new
content. That is a weak match, and `add` refuses it instead of guessing: the
error lists up to three candidates with their ID, type, first 120 characters,
`rank_score`, `text_overlap` and shared identifiers. Read them, then repeat
the add with `--update-id <id>` when one states the same fact, or with
`--create-new` when yours is a different fact. A create over a weak match
includes the passed-over record as `upsert_match` in the response.

`--update-id`, `--create-new` and `--upsert-match` replace the earlier
`--force` flag, which is no longer accepted.

## Replacing content

`--update-id` and a strong `--upsert-match` replace the stored content, so
they are subject to the same guard as [`update`](/machine/update#replacement-guard):
the write is refused when it drops a path, flag or symbol that no other active
memory mentions, or shares almost nothing with the stored content. Carry the
detail over, or pass `--allow-drop` when it is obsolete.

## Dry run

Preflight with `--dry-run` to see what the real write would do:

```sh
machine-memory add "New wording" --upsert-match "topic" \
  --dry-run (--local|--remote)
# {"command":"add","dry_run":true,"action":"update",
#  "would_match":{"id":42,"rank_score":88,"text_overlap":0.91,
#    "memory_type":"decision","status":"active","content_head":"...",
#    "shared_identifiers":["cli/src/app.ts"]},
#  "update_id":42,"replacement":{"action":"update",...},"size":{...}}
```

`--dry-run` never writes. `action` is what the real write does: `update`,
`create` or `refuse`. A refusal carries its reason in `note`, the weak
candidates in `candidates`, or the near-duplicate in `duplicate`. The command
exits `1` when the text is over budget or the write would be refused.

Content that is empty, `null` or `undefined` is refused: those are missing
values turned into text by a shell or a script.

## Options

`--path` adds the tags the [tag map](/machine/tag-map) assigns to one path or
to several separated by commas. The response lists `path_tag_matches`: each
path with the prefix that matched and the tags it added. A path that matches
no prefix adds no tags and is reported on stderr, as is a memory written
without any tags. `--tags` and `--context` store retrieval metadata. `--type` accepts `decision`, `convention`, `gotcha`,
`preference`, `constraint`, `reference`, or `status`. `--certainty` accepts
`verified`, `inferred`, or `speculative`. `--refs` accepts JSON or CSV
references, and `--expires-after-days` is useful for transient status.

## Evidence

Certainty says how sure a claim is; evidence says what it rests on.
`--evidence` takes a comma-separated list of the kinds that were actually
established:

| Kind                      | Meaning                                                 |
| ------------------------- | ------------------------------------------------------- |
| `user_requirement`        | The user explicitly asked for it or stated a preference |
| `observed_implementation` | The code currently behaves this way                     |
| `verified_mechanism`      | The underlying technical mechanism was confirmed        |
| `tested_behavior`         | End-user behavior was exercised in tests or real use    |

Observing the implementation does not establish intent or cross-platform
behavior, so record what is still unconfirmed with `--validation-gaps`: one
plain-text gap, or a JSON array of up to 16 gaps of at most 300 characters.

```sh
machine-memory add "Admin shortcuts fire only inside focused forms" \
  --type decision --certainty verified --evidence observed_implementation \
  --validation-gaps '["User intent unconfirmed","Safari and Windows untested"]' \
  (--local|--remote)
```

`--certainty verified` is rejected unless at least one evidence kind is given.
Evidence and gaps are stored metadata only: they are not embedded and do not
count toward the size limit. `get` and `list` return them as arrays,
and `--json-min` summaries include `evidence` plus a `validation_gap_count`.

`--from-file` and inline content are mutually exclusive. `--brief`,
`--json-min`, and `--quiet` select smaller responses; `--brief` reports
`related_count` instead of the `related` list.

## Size limit

A memory's embedded text (content, plus `Tags:` and `Context:` lines when set)
is at most 2,000 UTF-8 bytes. A longer write is refused before anything is
stored, and the error leads with the number of bytes to remove:

```sh
machine-memory add "long content..." --tags "area:cli" --remote
# error: Memory is over by 728 bytes of 2,000: content 2,713, tags 15,
#        context 0 bytes. Shorten it, or split it into one record per fact.
#        Nothing was written.
```

Preflight any text without writing with [`size`](/machine/size) or
`add --dry-run`. Every successful write reports how much room the record has
left, in every output mode:

```json
{ "id": 42, "size": { "bytes": 108, "remaining_bytes": 1892 } }
```
