Agents need a stable project instruction block so they scan and write memory the same way every session. For MCP-only setups that block talks about MCP tools, not `machine-memory` CLI flags.

The managed section lives between HTML markers and can be replaced safely:

```html
<!-- machine-memory:start -->
<!-- machine-memory:version 6 mcp -->
…
<!-- machine-memory:end -->
```

Everything outside the markers is preserved. The version line lets the CLI
tell a checkout that its block is older than the current one.

## Public script (no CLI)

From the repository root:

### macOS and Linux

```sh
curl -fsSL https://machine-memory.jfa.dev/init-mcp | bash
```

### Windows

```powershell
irm https://machine-memory.jfa.dev/init-mcp.ps1 | iex
```

This is the MCP counterpart to the [CLI install script](/installation). It:

1. Creates `AGENTS.md` if missing, or updates the managed block in place
2. Writes the MCP backend workflow (tool names, repository slug rules, size preflight, checklist)
3. Prints the backend and a pointer at this docs section

### Options

| Variable                   | Effect                                                                              |
| -------------------------- | ----------------------------------------------------------------------------------- |
| `MACHINE_MEMORY_AGENTS_MD` | Path to write (default `AGENTS.md`). Absolute or relative to the current directory. |

Examples:

```sh
# default ./AGENTS.md
curl -fsSL https://machine-memory.jfa.dev/init-mcp | bash

# custom path
MACHINE_MEMORY_AGENTS_MD=.agents/memory.md \
  curl -fsSL https://machine-memory.jfa.dev/init-mcp | bash
```

```powershell
# default ./AGENTS.md
irm https://machine-memory.jfa.dev/init-mcp.ps1 | iex

# custom path
$env:MACHINE_MEMORY_AGENTS_MD = ".agents/memory.md"
irm https://machine-memory.jfa.dev/init-mcp.ps1 | iex
```

Requirements: on macOS/Linux the `init-mcp` script needs `bash`, `base64`, and `python3`. The Windows `init-mcp.ps1` script needs PowerShell 5.1+ only (no extra dependencies).

## CLI equivalent

If the CLI is installed:

```sh
machine-memory init --mcp
```

Same managed block as the public script. Use `--local` or `--remote` when agents should follow CLI commands instead — see [init](/human/init).

Exactly one of `--local`, `--remote`, or `--mcp` is required.

## When to run it

- First time enabling MCP-only memory for a repo
- After changing the MCP workflow or tool surface you want agents to follow
- Safe to re-run: the block is replaced, not duplicated

## What agents get

The MCP block is about 2,500 bytes, because agents read it on every turn. It tells agents to:

- Pass the repository slug pinned in `.agents/machine-memory.json`, or the path of the checkout's origin remote when there is no pin, and check it with `list_repositories` before the first write
- Scan once before changing code with `memory_suggest` (known files) or `memory_query` (a topic, or a task that touches no files), then read the relevant records with `memory_get`, judging results by `match_strength`
- Follow the user when an instruction contradicts a stored record, and update the record
- Write one fact per record, keep delivery state in one expiring `status` record, and leave out pixel values, UI state, deploy outcomes and facts about one machine
- Preflight size with `memory_size`
- Read a record before `memory_update` and keep the details that still hold, or omit `content` to change only metadata; create with `memory_add` and `upsert_match`
- Restore details listed in `dropped` by mistake, and read the `review_candidates`, changing only those that rely on what changed
- Name `evidence` kinds for `certainty: verified`
- Keep memory writes with the parent agent when delegating
- Review the task's writes before the final response

The tool descriptions carry the detail: pagination, filters, defaults and the weak-match rule.

- Keep durable knowledge separate from delivery status; say whether work is local, committed, pushed, or deployed in an expiring `status` record
- Carry over unrelated details when replacing a record (`memory_diff` and `memory_update` report `dropped` details), and read the `review_candidates` that updates and deprecations return, changing only those that rely on what changed
- Let the parent agent own memory writes; child agents return persistence candidates with evidence
- Scan before edits, then run the end-of-task checkpoint: classify each finding as covered, new durable knowledge, superseded, transient status, or intentionally omitted

Full tool reference: [Tools](/docs/mcp/tools).
