## Prerequisites

`provision` creates the necessary cloud infrastructure for the remote DB.

Currently, it only supports Cloudflare as the remote memory provider.

For the stack to be deployed, you need to have access to a Cloudflare account with permissions to deploy:

- A Worker, that will be the API endpoint that interacts with the database via bindings.
- A D1 database, where the memories will be stored.
- A Vectorize index, where the memory embeddings will be stored for semantic search.
- A Workers AI binding, used to generate embeddings for memories and queries.

## Usage

```sh
machine-memory remote provision
```

This command deploys the [Alchemy stack](https://github.com/jfalava/machine-memory/tree/master/remote-db/cloudflare): a complete IaC solution that creates the necessary services for this tool to have a remote backend.

1. Creates the Worker API
2. Generates or reuses a Worker token
3. Saves the resulting URL and credentials in the operating system keychain

## Names and defaults

| Option            | Environment variable        | Default                    |
| ----------------- | --------------------------- | -------------------------- |
| `--stack-name`    | `MACHINE_MEMORY_STACK_NAME` | `machine-memory-remote-db` |
| `--database-name` | `MACHINE_MEMORY_DB_NAME`    | `machine-memory-db`        |
| `--api-name`      | `MACHINE_MEMORY_API_NAME`   | `machine-memory-api`       |

Flags take precedence over environment variables. Existing names stored with remote credentials are used next, followed by the defaults above.

```sh
machine-memory list --remote
```
